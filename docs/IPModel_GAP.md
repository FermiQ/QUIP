# IPModel_GAP.f95

## Overview

The `IPModel_GAP.f95` file defines the `IPModel_GAP_module`, which implements the Gaussian Approximation Potential (GAP). GAP is a sophisticated machine learning interatomic potential framework. It constructs a model of the potential energy surface by learning from reference quantum mechanical (QM) data (energies, forces, virials). This allows GAP models to achieve accuracies close to the QM reference method but at a significantly lower computational cost, making them suitable for large-scale molecular dynamics simulations.

The core idea of GAP is to use Gaussian Process (GP) regression to interpolate energies and forces based on descriptors of local atomic environments. These descriptors transform the Cartesian coordinates of an atom and its neighbors into a feature vector that captures the local geometry and chemical species, respecting rotational and permutational symmetries.

## Key Components

- **`MODULE IPModel_GAP_module`**: The main Fortran module for the GAP potential.
- **`TYPE IPModel_GAP`**: A derived data type that stores all parameters, the trained Gaussian Process model, and descriptor configurations. Key members include:
    - `cutoff`: Real(dp), the cutoff radius used for descriptor calculations, determining the extent of the local atomic environment.
    - `E_scale`: Real(dp), a global scaling factor applied to the predicted potential energy.
    - `e0(:)`: Real(dp), per-element reference energies (atomic energies) that are typically subtracted from total energies during training and added back during prediction.
    - `label`: Character string, an optional label for this potential instance.
    - `command_line`: Character string, stores the command line used to generate/train the GAP model.
    - `xml_version`: Integer, version of the XML format of the loaded GAP model.
    - **`my_gp`**: `TYPE(gpSparse)`, this is the central object holding the trained sparse Gaussian Process model. It includes the sparse set of representative atomic environments, their corresponding weights (alpha coefficients), and the GP hyperparameters (kernel parameters, noise variance).
    - **`my_descriptor(:)`**: Allocatable array of `TYPE(descriptor)`. Each element defines a specific atomic environment descriptor (e.g., SOAP, Bispectrum) used by the GP model. It includes parameters like cutoff radii, n_max, l_max, etc., specific to the descriptor type.

- **Core Subroutines and Functions**:
    - **`Initialise(this, args_str, param_str)` (Interface to `IPModel_GAP_Initialise_str`)**: Subroutine to initialize the GAP potential.
        - It parses `args_str` for settings like `label`, `E_scale`, and `gap_variance_regularisation`.
        - It parses `param_str` (an XML string, typically read from a GAP model file) using `IPModel_GAP_read_params_xml` and then `gp_readXML` to load the trained GP model into `this%my_gp` and configure the `this%my_descriptor` objects based on the information in the XML.
    - **`Finalise(this)` (Interface to `IPModel_GAP_Finalise`)**: Subroutine to deallocate resources, including the `gpSparse` model (`my_gp`) and `descriptor` objects (`my_descriptor`).
    - **`Print(this, file, dict)` (Interface to `IPModel_GAP_Print`)**: Subroutine to print information about the loaded GAP model, such as its label, cutoff, and the log-likelihood of the GP model.
    - **`Calc(this, at, ...)` (Interface to `IPModel_GAP_Calc`)**: The main routine for calculating energies, forces, and virials.
        1.  For each atom (or each unique atomic environment, depending on the parallelization strategy), it calls the `Calc` method of the relevant `descriptor` object(s) in `this%my_descriptor` to compute the descriptor vector for that environment.
        2.  This descriptor vector is then passed to the `gp_predict` function (from `gp_predict_module`) along with the trained GP model (`this%my_gp%coordinate(i_coordinate)`) to obtain the predicted local energy. If forces/virials are requested, `gp_predict` also returns the gradient of the energy with respect to the descriptor components.
        3.  The descriptor gradients are transformed back into Cartesian forces on individual atoms and contributions to the virial tensor using the chain rule and the Jacobian of the descriptor transformation (provided by the `descriptor` object's `grad_data`).
        4.  Optionally, it can compute an estimate of the variance of the GAP prediction (if `do_gap_variance` is true).
- **XML Parsing Handlers (`IPModel_startElement_handler`, `IPModel_endElement_handler`, `IPModel_characters_handler`)**: Internal routines used by the FoX XML library to parse the `param_str` that defines the trained GAP model.

## Important Variables/Constants

- **The Trained GAP Model (XML file)**: This is the most crucial external input. It's an XML file generated by GAP training codes (e.g., `gap_fit`). This file contains:
    - Gaussian Process hyperparameters (kernel parameters, signal variance, noise variance/regularization).
    - The "sparse set" of representative atomic environments and their associated weights (alpha coefficients).
    - Definitions and parameters for the descriptors used (e.g., SOAP, Bispectrum).
- **`my_gp` (`TYPE(gpSparse)`)**: The in-memory representation of the trained Gaussian Process.
- **`my_descriptor(:)` (`TYPE(descriptor)`)**: The in-memory representation of the descriptor configurations.
- **XML Tags**: Key tags within the GAP model XML file include `<GAP_params>`, `<GAP_data>`, `<gpCoordinates>`, `<descriptor>`, specific descriptor parameter tags (e.g., `<bispectrum_so4_params>`), and data arrays for the sparse set and GP parameters.

## Usage Examples

A trained GAP model (e.g., `gap_model.xml`) is specified in the input. This module is then used by `DynamicalSystem.f95` via the `Potential` interface.

```fortran
! Conceptual example of using a GAP potential
use Potential_module
use Atoms_module
use System_module

type(Potential) :: gap_potential
type(Atoms) :: my_atoms
real(dp) :: energy_val
real(dp) :: forces_val(3, my_atoms%N)
character(len=:), allocatable :: gap_xml_content

! Assume my_atoms is initialized
! call create_some_structure(my_atoms)
! call set_cutoff(my_atoms, 6.0_dp) ! Set an appropriate initial cutoff

! Read the content of the trained GAP XML file into gap_xml_content
! open(unit=file_unit, file="gap_model.xml", status="old", action="read")
! read(file_unit, "(A)", end=eof_reached) gap_xml_content_line
! ... (concatenate lines into gap_xml_content) ...
! close(file_unit)

! Initialize the GAP potential
call Initialise(gap_potential, args_str="IP GAP label=MyGAPModel", param_str=gap_xml_content)

! Calculate energy and forces
call Calc(gap_potential, my_atoms, energy=energy_val, force=forces_val)
call print("GAP Energy: ", energy_val)

! Clean up
call Finalise(gap_potential)
call Finalise(my_atoms)
```

## Dependencies and Interactions

- **`Potential_module` (via `IPModel_interface.h`)**: `IPModel_GAP_module` implements the standard potential interface, allowing it to be used polymorphically by modules like `DynamicalSystem.f95`.
- **`atoms_module` (`Atoms_types_module`)**: The `Calc` routine and the descriptor calculation routines take an `Atoms` object as input to access atomic positions, species, and neighbor information.
- **`descriptors_module`**: This is a critical dependency (enabled by `#ifdef HAVE_GAP`). It provides the `TYPE(descriptor)` and the routines to compute various atomic environment descriptors (e.g., SOAP, Bispectrum) and their derivatives with respect to atomic positions.
- **`gp_predict_module`**: Also critical (enabled by `#ifdef HAVE_GAP`). It provides the `TYPE(gpSparse)` for storing the Gaussian Process model and the `gp_predict` function to make energy and force predictions based on input descriptors.
- **`System_module`**: For fundamental utilities such as double precision kind (`dp`), I/O (`inoutput`, `print`), error handling (`system_abort`), and string manipulation.
- **`dictionary_module`, `paramreader_module`**: Used for parsing the `args_str` during initialization.
- **`QUIP_Common_module`**: Provides XML parsing utilities (FoX wrappers) for reading the GAP model file.
- **`linearalgebra_module`**: May be used by descriptor or GP modules for matrix/vector operations.
- **`mpi_context_module`**: For MPI support, enabling parallelization of GAP calculations, potentially at the level of distributing descriptor calculations or atomic environments.

The `IPModel_GAP_module` integrates machine learning capabilities (Gaussian Processes and atomic environment descriptors) into the QUIP framework, allowing for QM-accurate simulations. Its effective use depends on a well-trained GAP model provided in an external XML file.
